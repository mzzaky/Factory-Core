v1.2.6 Update Log

=== Custom Main Menu GUI ===

- [New] Memisahkan semua properti visual Main Hub GUI dari hardcode ke file konfigurasi `custom_gui/main_menu.yml`.
- [New] Admin sekarang dapat mengubah title GUI, ukuran (size), border material, dan custom model data langsung dari config.
- [New] Semua item pada Main Hub kini memiliki field `slot`, `material`, `custom_model_data`, `name`, `lore`, dan `sound` yang dapat dikustomisasi secara interaktif.
- [New] Menambahkan fitur "multi-slot": properti `slot` pada item kini mendukung 3 format (integer tunggal, string dengan koma "20, 21", atau YAML list). Item akan ditempatkan di semua slot yang dikonfigurasi secara bersamaan.
- [New] Menambahkan field `enabled` (true/false) pada setiap item dan border. Item dapat disembunyikan kapan saja hanya dengan mengubah nilainya menjadi false atau menghapus seluruh section itemnya dari file yaml.
- [New] Efek suara (sound) saat mengklik item dapat diatur individual per item (`sound`, `volume`, `pitch`). Config juga mendukung default click sound sebagai fallback jika item tidak menetapkan suara khususnya.
- [Update] HubGUI.java dan HubClickListener.java telah direfactor penuh untuk membaca tampilan dan suara dari `main_menu.yml` serta menampung multi-slot placement logic. Data placeholder dinamis (seperti stat pemain) tetap disuntikkan oleh plugin saat runtime.
- [Update] Menambahkan mekanisme fallback otomatis. Jika `main_menu.yml` dihapus, rusak, atau ada konfigurasi yang hilang, GUI akan otomatis kembali ke default hardcoded sebelumnya tanpa menyebabkan error.
- [Update] Perintah `/fc admin reload` sekarang juga me-reload konfigurasi `custom_gui/main_menu.yml`. Admin bisa mengubah tampilan dan menerapkannya seketika tanpa perlu merestart server.

=== GUI ID System & open_gui_* Special Actions ===

- [Fix] The main Hub menu items had no function when clicked if their display name was changed.
         Clicks were previously routed by matching the item's display name (e.g. the listener
         checked name.contains("Factory Browse")), which broke silently whenever an admin
         renamed any item in main_menu.yml.
- [New] Every main-menu item now receives a stable internal "hub_gui_id" Persistent Data
         Container (PDC) tag stamped at build time (e.g. "factory_browse", "invoice_center").
         The click listener uses this ID tag for routing — the display name is now irrelevant.
         Items can be freely renamed without losing their click action.
- [New] Added 10 new "open_gui_*" special actions for the on_click field in main_menu.yml:
           open_gui_factory_browse   — opens Factory Browse GUI
           open_gui_my_factories     — opens My Factories GUI
           open_gui_invoice_center   — opens Invoice Center GUI
           open_gui_tax_center       — opens Tax Center GUI
           open_gui_employees_center — opens Employees Center GUI
           open_gui_marketplace      — opens Marketplace GUI
           open_gui_achievements     — opens Achievements GUI
           open_gui_research_center  — opens Research Center GUI
           open_gui_daily_quests     — opens Daily Quests GUI
           open_gui_help_info        — opens Help & Info GUI
         These actions can be assigned to ANY item slot, enabling custom shortcut buttons.
         Example usage in main_menu.yml:
           on_click: open_gui_invoice_center
- [Update] main_menu.yml header now documents all open_gui_* actions and lists every
            registered GUI ID so admins have a full reference without reading source code.
- [Update] Each item section in main_menu.yml now has a "GUI ID" comment line showing
            its internal ID and the matching on_click value for quick reference.

File Modified:
  - src/main/resources/custom_gui/main_menu.yml (Added full open_gui_* documentation and per-item GUI ID comments)
  - src/main/java/com/aithor/factorycore/gui/HubGUI.java (Added stampGuiId(); all items now stamped with hub_gui_id PDC tag; expanded stampOnClick() Javadoc)
  - src/main/java/com/aithor/factorycore/listeners/HubClickListener.java (Rewrote handleHubClick() to route by hub_gui_id; extended executeOnClick() to handle all open_gui_* actions)

=== Vanilla Input Recipes & Smeltery ===

- [New] Menambahkan pabrik jenis baru: `Smeltery` sebagai pabrik entry-point. Pabrik ini dikhususkan untuk memproses material vanilla asli (seperti ore hasil tambang) menjadi raw resources yang terdaftar di plugin.
- [New] Mesin resep (Recipe Engine) sekarang mendukung prefix `vanilla:` pada `recipes.yml` (contoh: `vanilla:IRON_ORE`). Jika prefix ini digunakan, plugin akan mencocokkan item langsung menggunakan Material Bukkit asli (mengabaikan plugin resource ID dan melarang penggunaan custom-model-data item sebagai substitusi material asli).
- [New] Menambahkan 12 resep Smeltery default di `recipes.yml` yang mencakup peleburan untuk semua jenis ore standar (Iron, Coal, Copper, Gold, Diamond, Redstone), varian Deepslate dengan imbalan hasil lebih tinggi, dan batch smelting untuk item mentah hasil Fortune pickaxe (Raw Iron/Copper/Gold).
- [Update] `ResourceManager.java` diperbarui secara menyeluruh dengan kumpulan fungsi pembantu (`isVanillaInput`, `getVanillaMaterial`, `getVanillaDisplayName`, dll.) untuk memisahkan dan menangani material vanilla dengan aman.
- [Update] Implementasi penuh sistem setor/tarik pada GUI penyimpanan (`FactoryGUI`, `StorageGUI`). Pemain sekarang dapat menyetorkan material vanilla ke dalam input storage Smeltery menggunakan shift-click, dan fungsi "Deposit All" kini cukup cerdas memindai dan memasukkan item vanilla yang dibutuhkan otomatis berdasarkan resep aktif pabrik.
- [Update] Konfigurasi default ditambahkan secara mulus pada `config.yml`, `resources.yml`, dan `FactoryType.java` dengan komentar dokumentasi yang informatif mengenai cara kerja input vanilla.

=== Player Factory Creation System (Self-Service Factory Apartments) ===

- [New] Players can now create their own factory regions without needing admin intervention or WorldGuard.
         A new "Create Factory" button has been added to the Factory Browse GUI (FactoryBrowseGUI.java).
         Clicking it opens a factory type selection sub-menu where players choose the type they want to build.
- [New] Each factory type has a configurable creation price under `player-factory.creation-prices` in config.yml.
         Prices are independent from admin-assigned factory base prices.
- [New] After selecting a factory type, a confirmation GUI shows region size, location, price, and balance info.
         Upon confirmation, a 3D region is automatically registered centered on the player's position:
           - Horizontal radius: configurable via `player-factory.region-radius` (default: 3 blocks each direction)
           - Vertical height: configurable via `player-factory.region-height-up` and `region-height-down`
- [New] World whitelist: admins can restrict which worlds allow player factory creation via
         `player-factory.allowed-worlds` in config.yml. Leave empty to allow all worlds.
- [New] Factory ownership limit: configurable via `player-factory.max-per-player` (default: 3).
         Bypass permission: `factorycore.bypass.player-factory-limit`
- [New] Region overlap detection: the system prevents players from creating factories that overlap
         with any existing player-created factory region.
- [New] Region protection: blocks within a player factory region cannot be broken or placed by anyone
         except the factory owner and players with `factorycore.admin` permission.
         Configurable via `player-factory.protection.enabled` in config.yml.
- [New] Sell-price-multiplier integration: player-created factories use the same `factory.sell-price-multiplier`
         from config.yml (default: 50% of creation price) when sold.
- [New] Toggle Border function added to the factory MainMenuGUI. When clicked, particle effects
         (configurable particle type via `player-factory.border-particle`) are displayed at all edges
         and corners of the player's factory region to help visualize boundaries.
         Particle spacing and interval are configurable.
- [New] Player-created factories are displayed in the "My Factories" GUI alongside admin-created ones,
         marked with a purple "[Player]" tag for distinction.
- [New] Fast Travel support: player-created factories can be teleported to using the factory menu's
         Fast Travel button (teleports to the center/creation location).
- [New] Sound effects: factory creation plays ENTITY_PLAYER_LEVELUP, border toggle plays BLOCK_NOTE_BLOCK_PLING.
         All sounds configurable under `notifications.sound` in config.yml.
- [New] Title notifications: factory creation and border toggle display animated titles.
         All title text is configurable in language.yml under `titles.player-factory-created`,
         `titles.player-factory-border-on`, and `titles.player-factory-border-off`.
- [New] 10 new configurable messages added to language.yml for all player factory actions:
         player-factory-created, player-factory-world-not-allowed, player-factory-limit-reached,
         player-factory-overlap, player-factory-protected, player-factory-sold,
         player-factory-border-enabled, player-factory-border-disabled, player-factory-no-factories.
