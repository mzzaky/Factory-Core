Bug Fixes
  • Fixed an issue where the "Factories Owned" counter in MyFactoriesGUI did not count player-created factories.
  • Fixed an issue in MyFactoriesGUI where it read the wrong config key for factory limit (factory.max-ownership instead of factory.max-factories-per-player).
  • Fixed an issue where the /fc sell <factory_id> command failed to work for player-created factories, as it only checked the admin FactoryManager.
  • Fixed tab-complete for /fc sell, /fc tp, and /fc gui to correctly include player-created factory IDs.
  • Fixed FactoryCore PlaceholderAPI placeholders (%factorycore_factories_owned%, %factorycore_factories_running%, %factorycore_total_value%, %factorycore_highest_level%) not including statistics from player-created factories.
  • Fixed an issue where player-created factories did not appear in the Employee Shop and Employees Center GUIs, preventing players from assigning employees to them.
  • Fixed an issue in MarketplaceGUI where clicking items in the player's inventory to register them for sale did not work due to hub GUI click prevention logic.
  • Fixed a critical core bug where production cycles and upgrade timers for player-created factories never progressed because their manager wasn't hooked into the central server scheduler.
  • Fixed a massive synchronization issue where multiple actions inside the Factory Menu (Start Production, Access Recipes, Upgrade, Manage Storage) refused to work or threw errors for player-created factories due to only checking the admin Factory manager.
  • Fixed an issue where the sell confirmation prompt in My Factories menu would fail to open/process for player-created factories.
  • Added full support for vanilla input materials to deposit and withdraw correctly from player-created factories, mirroring the behavior of admin factories.
  • Fixed an issue where internal Hub GUI placeholders (like {factory_owned_count}, {factory_running_count}, {factory_total_value}) and the "Assigned Employees" counter ignored player-created factories.
  • Fixed the Quick Stats breakdown menu in the Hub GUI to correctly include and display a player's admin factories and player-created factories together.
  • Fixed an issue where player-created factories were not assessed for taxes — TaxManager now calculates and tracks tax records for both admin and player-created factories.
  • Fixed an issue where player-created factories were not included when paying taxes individually, paying all taxes at once, or retrieving tax totals/records.
  • Fixed an issue where late fee notifications for overdue taxes only notified admins, not player-factory owners.
  • Fixed an issue where employee salary invoices were only generated for admin-created factories. PlayerFactory employees now also generate salary invoices on the same cycle, applying research salary reductions as expected.
  • Fixed an issue in InvoiceCenterGUI where invoice items from player-created factories always displayed "Unknown" as the factory name, as it only looked up the factory ID from the admin FactoryManager. Factory type (Admin/Player) is now also shown on each invoice item.
  • Fixed an issue in TaxCenterGUI where player-created factories were not listed in the Tax Center menu, not counted in the "Factories Taxed" header stat, and excluded from the Tax Calculator preview. The Tax Center now shows both admin and player factories side-by-side, with their type clearly labeled.
  • Fixed a critical issue in NPCManager where employees assigned to player-created factories caused a continuous "Respawning missing NPC" loop in the console. The root causes were: (1) spawnNPCWithTemplate() only validated factory IDs against the admin FactoryManager, causing NPC spawns for player factories to silently fail; (2) the respawn scheduler had no guard for orphaned NPC records whose factory no longer exists, causing it to retry respawning indefinitely. Additionally, a hotfix was implemented to automatically "unassign" any orphaned NPCs (returning them to the player's employee pool) if they are detected in a deleted/sold player factory. Player factories now also properly unassign NPCs immediately when the factory is sold.
  • Fixed OutputStorageGUI so it can now be opened correctly by player-created factories. Previously, the GUI lookup strictly checked the admin FactoryManager, causing it to fail silently when a player factory's NPC was left-clicked. Items can now be safely withdrawn (including vanilla items).
  • Fully synchronized the crafting/production completion mechanism for player-created factories in PlayerFactoryManager. Completing production in a player factory now correctly awards the "early_prototype" and "mass_producer" achievements, adds progress to the "Industrial Hustle" daily quest, and triggers the configured completion sound and title notifications, exactly mirroring admin factories.
  • Improved MyFactoriesGUI item names and lore for better readability. Huge raw UUID values have been reformatted to display only the first 8 characters and are enclosed cleanly in parentheses (e.g. Iron Smeltery (#a1b2c3d4) instead of massive raw strings). The full ID remains functional for background event clicks.
  • Fixed an issue where the BossBar for player-created factories did not appear when production started. Production in player factories now properly creates, updates, and removes BossBars in the exact same manner as admin factories.
  • Fixed an issue where BossBars for both admin and player-created factories would disappear and fail to recreate if the server restarted while production was running, or if a player disconnected and reconnected. BossBars are now lazily recreated and correctly reattached to players upon reconnecting.
  • Fixed an issue where the "industrial_mastery" research buff (additional factory limit) was ignored when players attempted to create new player factories.
  • Fixed an issue in RecipeConfirmationGUI where production time and cost reductions from research buffs were not visually calculated and displayed in the confirmation lore.
+
New Features
  • Achievement Rewards System:
    • Added on-complete configuration block to achievement.yml to support custom rewards when an achievement is completed.
    • Supports executing one or multiple commands automatically (with %player% placeholder).
    • Supports playing custom sound effects alongside rewards (e.g., sound: UI.TOAST.CHALLENGE_COMPLETE).
    • Commands are processed properly even if the final achievement progress occurs while the player is offline.
  • MySQL Database Support:
    • Implemented full MySQL database support as configured in config.yml (database.type: MYSQL).
    • Added DatabaseManager that handles MySQL connections with auto-reconnect and connection validation.
    • When MySQL is enabled, all 11 data files (factories, player_factories, input-storage, output-storage, invoices, npcs, marketplace, taxes, achievements, daily-quests, research) can be stored in MySQL tables.
    • Added data migration commands to transfer data between YAML and MySQL:
      • /fc admin database status — View current database connection status (YAML or MySQL).
      • /fc admin database migrate yaml-to-mysql — Migrate all existing YAML data files into MySQL tables.
      • /fc admin database migrate mysql-to-yaml — Export all MySQL data back to YAML files.
    • MySQL tables use InnoDB engine with utf8mb4 charset for full Unicode support.
    • Connection auto-recovery: if the MySQL connection drops, it automatically reconnects on next data operation.
    • Database status is displayed in the startup banner.
  • Comprehensive Backup System:
    • Added a full backup system for the plugin's data folder with ZIP compression.
    • Backups can be managed via /fc admin backup <event> commands:
      • /fc admin backup start [label] — Create a new backup (optional label for identification).
      • /fc admin backup restore <filename> — Restore a backup (automatically creates a safety backup before restoring).
      • /fc admin backup list — List all available backups with file size and date.
      • /fc admin backup delete <filename> — Delete a specific backup file.
      • /fc admin backup auto — Toggle automatic scheduled backups on/off.
      • /fc admin backup status — View backup system status (auto-backup state, interval, backup count).
    • Automatic backup system with configurable toggle and interval in config.yml (backup.auto-backup).
    • Configurable maximum backup retention (backup.max-backups) — oldest backups are automatically deleted when the limit is exceeded.
    • Safety mechanism: restoring a backup always creates a pre-restore safety backup first, preventing accidental data loss.
    • All backup operations are logged to the FactoryCore log file.
    • Tab-completion support for all backup subcommands, including backup filenames for restore/delete.
    • Backup system status is displayed in the startup banner.

Configuration Changes
  • config.yml: Updated database.type comment — MySQL is now fully supported (no longer "coming soon").
  • config.yml: Added backup section with max-backups, auto-backup.enabled, and auto-backup.interval-ticks.
  • language.yml: Added backup messages (backup-created, backup-restored, backup-deleted, backup-failed, etc.).
  • language.yml: Added database messages (database-connected, database-migration-start, etc.).
  • language.yml: Added help entries for backup and database admin commands.
  • plugin.yml: Added factorycore.admin.backup and factorycore.admin.database permissions (default: op).

New Features
  • Custom Main Menu GUI: Separated all visual properties of the Main Hub GUI from hardcode into the custom_gui/main_menu.yml configuration file. Admins can now change the GUI title, size, border material, and custom model data directly from the config.

  • Language Configuration: Added 10 new configurable messages to language.yml for all player factory actions.

  • Configuration Documentation: main_menu.yml header now documents all open_gui_* actions and lists every registered GUI ID. Each item section has a "GUI ID" comment line.

  • Vanilla Item Handling: ResourceManager.java thoroughly updated with helper functions to securely handle vanilla materials. Full implementation of deposit/withdraw system on storage GUIs for vanilla materials.

Factory System

Resource System
  • 21 Resources in 5 Categories:
    • Raw Resources (6): Iron Ore, Coal Ore, Copper Ore, Gold Ore, Diamond Ore, Redstone Dust

  • Enchantment Glow Effect for rare items (Gold Alloy, Diamond Ore, Premium Fuel, Circuit Board, Hydraulic System, and all Final Resources).
+
Economy & Tax System
  • Full Vault Integration for all economic transactions (buy, sell, tax, salary, marketplace).
  • Tax System: 5% of factory price per 3 Minecraft days (144,000 ticks). +2.5% per factory level. 7-day grace period before overdue. 5% late fee on overdue taxes.
  • Salary System: 1% of factory price per 1 Minecraft day (24,000 ticks), automatically billed as invoices.
  • Invoice Management: Auto-generated invoices for tax and salary. Supports individual or bulk payment. Factory is disabled on unpaid overdue invoices.
+
NPC Employee System
  • 5 Employee Tiers available in the Employee Shop:
    • Apprentice Worker — $500 (salary $50): −5% production time

    • Master Engineer — $6,000 (salary $450): −35% production time
  • Advanced NPC Behavior: Head tracking (6-block radius), idle animations with smooth interpolation, unique particle effects per factory type, hologram display, ambient/interaction sounds, body rotation, invulnerable & AI-disabled.
  • 4 NPC Templates matching factory types: Steel Mill Worker (ARMORER/PLAINS), Refinery Operator (TOOLSMITH/DESERT), Workshop Engineer (WEAPONSMITH/SNOW), Advanced Factory Manager (LIBRARIAN/JUNGLE).
