Overview

FactoryCore provides native, out-of-the-box support for MMOItems! This tight integration allows you to utilize your pre-configured custom MMOItems globally across the FactoryCore ecosystem.

💡 Endless Possibilities
Use extremely powerful custom weapons, armors, and stat-infused consumables as direct factory outputs, craftable recipes, or even standard resources within your industrial empire!

How to Setup

Linking an MMOItem to FactoryCore is incredibly easy. FactoryCore automatically detects MMOItems upon startup - no extra configuration toggles are needed. Simply map your items inside the resources.yml file using two essential attributes:

  • mmoitems-type: Represents the structural type of the MMOItem (e.g., SWORD, ARMOR, MATERIAL, CONSUMABLE).
  • mmoitems-id: The unique specific identifier or name of the MMOItem itself (e.g., STEEL_SWORD).

Once defined, FactoryCore essentially bridges the plugin borders. The defined item acts identically to a native factory resource, smoothly working in the Marketplace, Factory Output storages, and input requirements!

Configuration Examples

Below is a working example demonstrating how to register an MMOItem as a standard FactoryCore resource in your resources.yml:

YAML 
resources:
  mmo_steel_sword:
    # The FactoryCore internal category (e.g. RAW_RESOURCES, PROCESSED_GOODS)
    type: "PROCESSED_GOODS"
    
    # The base fallback material if MMOItems is ever disabled
    material: "IRON_SWORD"
    name: "&fSteel Sword"
    
    # === MMOITEMS HOOK ===
    mmoitems-type: "SWORD"
    mmoitems-id: "STEEL_SWORD"
    
    # Marketplace suggested price config (FactoryCore logic)
    suggested_price: 1500.0
⚖️ Attribute Overrides
When mmoitems-type and mmoitems-id are defined correctly, FactoryCore heavily prioritizes the MMOItems data. Base graphical properties like material, name, lore, and custom-model-data will be visually overridden by the native MMOItem structure, while preserving internal attributes like suggested_price.

Tips & Tricks

🛠️ Recipes Integration
Just like any other item, your mapped MMOItem resource ID (e.g., mmo_steel_sword) can become a recipe output! When your factory completes a production cycle, it will perfectly generate an exact clone of your MMOItem, complete with randomized stat rolls and abilities!
  • If the server owner accidentally uninstalls or temporarily disables MMOItems, FactoryCore possesses a graceful fallback system. It will safely revert to rendering the base material, name, and lore so your economy doesn't break.
  • Because MMOItems generate varying NBT data per item drop (like varying attack damage), FactoryCore validates items efficiently and flawlessly recognizes any copy of the item by checking its innate NBT baseline ID markers.
  • Always ensure the mmoitems-type respects the capitalization format you use inside MMOItems to prevent registry lookup failures.
